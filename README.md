## 🔀 Merge Sort

Сортировка слиянием. Стабильная, с гарантированной сложностью `O(n log n)`, но требует дополнительной памяти под временные массивы.

### Базовая версия

Рекурсивно делим массив пополам, пока не останутся подмассивы из 0 или 1 элемента (они уже отсортированы), затем сливаем пары отсортированных подмассивов обратно: сравниваем головы обеих частей и добавляем в результат меньший элемент, пока одна из частей не закончится, а остаток второй части просто дописываем в конец. На каждом уровне рекурсии создаются новые списки, исходный массив при этом не меняется.

Пример на массиве `[6, 1, 9, 2, 8]`

Разбиение (делим пополам, пока не останутся элементы по одному):

- `[6, 1, 9, 2, 8]` → `[6, 1]` и `[9, 2, 8]`
- `[6, 1]` → `[6]` и `[1]`
- `[9, 2, 8]` → `[9]` и `[2, 8]`
- `[2, 8]` → `[2]` и `[8]`

Слияние (снизу вверх, попарно):

- `merge([6], [1])` → `[1, 6]`
- `merge([2], [8])` → `[2, 8]`
- `merge([9], [2, 8])` → `[2, 8, 9]`
- `merge([1, 6], [2, 8, 9])` → `[1, 2, 6, 8, 9]`

<details>
<summary>Показать код</summary>

```python
def merge(left: list[int], right: list[int]) -> list[int]:
    p1 = p2 = 0
    res: list[int] = []

    while p1 < len(left) and p2 < len(right):
        if left[p1] <= right[p2]:
            res.append(left[p1])
            p1 += 1
        else:
            res.append(right[p2])
            p2 += 1

    res.extend(left[p1:])
    res.extend(right[p2:])
    return res


def merge_sort(nums: list[int]) -> list[int]:
    if len(nums) <= 1:
        return nums

    mid = len(nums) // 2

    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])

    return merge(left, right)
```

</details>

**Сложность:** время `O(n log n)`, память `O(n)`

### In-place версия

Та же идея разделяй и властвуй, но без пересоздания списков на каждом шаге. Рекурсия работает с границами `l, r` внутри одного и того же массива `nums`. Под буфер копируется только левая половина, правая половина остаётся на месте, а результат сразу записывается обратно в `nums`. Если буфер заканчивается раньше правой половины, значит остаток правой части уже стоит на нужных местах и докопировать его не нужно, дописать нужно только хвост буфера, если он остался.

Пример на массиве `[6, 1, 9, 2, 8]`

Разбиение (по границам `l, r`, без копирования массива):

- `[0, 5)`, mid = 2 → `[0, 2)` и `[2, 5)`
- `[0, 2)`, mid = 1 → `[0, 1)` и `[1, 2)` (по 1 элементу, база рекурсии)
- `[2, 5)`, mid = 3 → `[2, 3)` (база) и `[3, 5)`
- `[3, 5)`, mid = 4 → `[3, 4)` и `[4, 5)` (по 1 элементу, база рекурсии)

Слияние (буфер только для левой половины, пишем сразу в `nums`):

- merge `nums[0:1]` и `nums[1:2]` → `nums[0:2] = [1, 6]`, массив `[1, 6, 9, 2, 8]`
- merge `nums[3:4]` и `nums[4:5]` → `nums[3:5] = [2, 8]`, массив без изменений `[1, 6, 9, 2, 8]`
- merge `nums[2:3]` и `nums[3:5]` → `nums[2:5] = [2, 8, 9]`, массив `[1, 6, 2, 8, 9]`
- merge `nums[0:2]` и `nums[2:5]` → `nums[0:5] = [1, 2, 6, 8, 9]`, массив `[1, 2, 6, 8, 9]`

<details>
<summary>Показать код</summary>

```python
def merge_sort(nums: list[int], l: int = 0, r: int = None) -> list[int]:
    if r is None:
        r = len(nums)

    if r - l <= 1:
        return nums

    mid = (l + r) // 2
    merge_sort(nums, l, mid)
    merge_sort(nums, mid, r)

    buf = nums[l:mid]
    p1, p2, idx = 0, mid, l
    len_buf = len(buf)

    while p1 < len_buf and p2 < r:
        if buf[p1] <= nums[p2]:
            nums[idx] = buf[p1]
            p1 += 1
        else:
            nums[idx] = nums[p2]
            p2 += 1
        idx += 1

    if p1 < len_buf:
        nums[idx : idx + (len_buf - p1)] = buf[p1:]

    return nums
```

</details>

**Сложность:** время `O(n log n)`, память `O(n)`

## ⚡ Quick Sort

Быстрая сортировка. В среднем работает быстрее Merge Sort и не требует линейной дополнительной памяти, но без удачного выбора опорного элемента может деградировать до `O(n²)`.

### Базовая версия

Опорный элемент (pivot) выбирается как медиана из первого, среднего и последнего элементов массива, это заметно снижает шанс попасть в худший случай на уже отсортированных или почти отсортированных данных. Дальше массив разбивается на три части: меньше пивота, равные пивоту и больше пивота. Крайние части сортируются рекурсивно, а результат склеивается обратно.

Пример на массиве `[6, 1, 9, 2, 8]`

- Пивот: медиана из `6, 9, 8` → `8`
- `left = [6, 1, 2]`, `pivots = [8]`, `right = [9]`
- `quick_sort([6, 1, 2])`: пивот `2`, `left = [1]`, `pivots = [2]`, `right = [6]` → `[1, 2, 6]`
- `quick_sort([9])` → `[9]`
- Итог: `[1, 2, 6] + [8] + [9]` → `[1, 2, 6, 8, 9]`

<details>
<summary>Показать код</summary>

```python
def quick_sort(nums: list[int]) -> list[int]:
    if len(nums) <= 1:
        return nums

    a, b, c = nums[0], nums[len(nums) // 2], nums[-1]
    pivot = a + b + c - min(a, b, c) - max(a, b, c)

    left = [x for x in nums if x < pivot]
    pivots = [x for x in nums if x == pivot]
    right = [x for x in nums if x > pivot]

    return quick_sort(left) + pivots + quick_sort(right)
```

</details>

**Сложность**
- Среднее и лучшее: время `O(n log n)`, память `O(n log n)`
- Худшее: время `O(n²)`, память `O(n²)`

### In-place версия

Более экономная по памяти версия на разбиении Хоара: без создания новых списков, работает прямо внутри исходного массива. Два указателя двигаются навстречу друг другу: `left` вправо, пока значение меньше пивота, `right` влево, пока значение больше пивота. Как только оба останавливаются, элементы меняются местами и раунд повторяется, пока указатели не пересекутся.

Первый шаг на массиве `[6, 1, 9, 2, 8]`: пивот, как и раньше, `8`. После первого прохода указателей `9` и `8` меняются местами, массив становится `[6, 1, 8, 2, 9]`, и элемент `9` сразу занимает финальную позицию. Дальше та же логика повторяется рекурсивно уже на подмассивах слева и справа от точки разбиения.

<details>
<summary>Показать код</summary>

```python
def quick_sort(nums: list[int]) -> list[int]:
    help_func(nums, 0, len(nums) - 1)
    return nums


def partition(nums, left, right) -> int:
    low, med, high = nums[left], nums[(left + right) // 2], nums[right]
    pivot = low + med + high - max(low, med, high) - min(low, med, high)

    while True:
        while nums[left] < pivot:
            left += 1
        while nums[right] > pivot:
            right -= 1

        if left >= right:
            return right

        nums[left], nums[right] = nums[right], nums[left]
        left += 1
        right -= 1


def help_func(nums, left, right) -> None:
    if right <= left:
        return

    index = partition(nums, left, right)
    help_func(nums, left, index)
    help_func(nums, index + 1, right)
```

</details>

**Сложность**
- Лучшее и среднее: время `O(n log n)`, память `O(log n)`
- Худшее: время `O(n²)`, память `O(n)`

## 🧩 Insertion Sort

Сортировка вставками. Левая часть массива всегда отсортирована и в начале состоит из одного элемента. Дальше берём следующий элемент и вставляем его на нужную позицию в отсортированной части, сохраняя порядок и расширяя её. Повторяем, пока не отсортируем весь массив.

Пример на массиве `[6, 1, 9, 2, 8]`

- Проход 0: `[6 | 1, 9, 2, 8]`, в начале только `6` в отсортированной части
- Проход 1: `[1, 6 | 9, 2, 8]`
- Проход 2: `[1, 6, 9 | 2, 8]`
- Проход 3: `[1, 2, 6, 9 | 8]`
- Проход 4: `[1, 2, 6, 8, 9 |]`, неотсортированная часть опустела, массив готов

<details>
<summary>Показать код</summary>

```python
def insertion_sort(nums: list[int]) -> None:
    for k in range(1, len(nums)):
        i = k
        while i > 0 and nums[i] < nums[i - 1]:
            nums[i], nums[i - 1] = nums[i - 1], nums[i]
            i -= 1
```

</details>

**Сложность**
- Лучшее (почти отсортированный массив): `O(n)`
- Среднее и худшее: `O(n²)`
- Память: `O(1)`

## 🫧 Bubble Sort

Пузырьковая сортировка. Проходим по массиву и сравниваем соседние элементы, если левый больше правого, меняем их местами. За каждый проход самый крупный из оставшихся элементов всплывает в конец.

### Базовая версия

Пример на массиве `[6, 1, 9, 2, 8]`

- Проход 1: `6 > 1` меняем, `6 < 9` не меняем, `9 > 2` меняем, `9 > 8` меняем → `[1, 6, 2, 8, 9]`
- Проход 2: `1 < 6` не меняем, `6 > 2` меняем, `6 < 8` не меняем → `[1, 2, 6, 8, 9]`
- Проход 3-4: сравнения больше ничего не меняют, массив уже отсортирован

<details>
<summary>Показать код</summary>

```python
def bubble_sort(nums: list[int]) -> None:
    n = len(nums)
    for i in range(n - 1):
        for j in range(n - i - 1):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
```

</details>

**Сложность:** время `O(n²)`, память `O(1)`

> [!TIP]
> Без флага `swapped` эта же реализация всегда проходит массив полностью, даже если он уже отсортирован. Поэтому лучший случай тоже становится `O(n²)`

### Версия с флагом

Лучший случай это уже отсортированный массив

Пример на массиве `[1, 2, 6, 8, 9]`

- Проход 1: `1 < 2`, `2 < 6`, `6 < 8`, `8 < 9`, ни одного обмена за весь проход
- `swapped` остался `False`, значит массив уже отсортирован → выходим из цикла сразу, не делая оставшиеся `n-2` прохода

Именно эта проверка и даёт лучший случай `O(n)`: без неё алгоритм всегда делает все `n-1` проходов, даже по уже готовому массиву.

<details>
<summary>Показать код</summary>

```python
def bubble_sort(nums: list[int]) -> None:
    n = len(nums)
    for i in range(n - 1):
        swapped = False
        for j in range(n - i - 1):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                swapped = True
        if not swapped:
            break
```

</details>

**Сложность**
- Лучшее (уже отсортированный массив): `O(n)`
- Среднее и худшее: `O(n²)`
- Память: `O(1)`
